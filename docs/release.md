# Release guide

This guide describes how raftlab is released: the tag rules, what the Release workflow produces, the dry run, the local equivalent, how to verify a release, first-run caveats, and the post-push checklist.

## 1. Cutting a release

The version is taken from the tag. There is no manual version bump in any file.

```
git tag -a v1.2.3 -m "raftlab 1.2.3" && git push origin v1.2.3
```

Tags must match `vMAJOR.MINOR.PATCH[-PRERELEASE]`, for example `v1.2.3` or `v1.2.3-rc.1`. Any other tag fails the `build` job. A hyphen in the version makes a pre-release: the GitHub Release is marked as pre-release and the image gets no `latest` tag.

## 2. What the workflow produces

The workflow is `.github/workflows/release.yml`. It has four jobs.

| Job | Trigger | Permissions | Outputs |
|-----|---------|-------------|---------|
| `build` | tag push `v*` or `workflow_dispatch` | `contents: read` | `version`, `prerelease`; artifact `release-dist` |
| `image-dry-run` | `workflow_dispatch` only (needs `build`) | `contents: read` | Docker image `raftlab:<version>` built locally, not pushed |
| `publish-image` | tag push `v*` only (needs `build`) | `contents: read`, `packages: write` | image `ghcr.io/<owner>/<repo>:<version>` and `:latest` (not for pre-releases) |
| `publish-release` | tag push `v*` only (needs `build` and `publish-image`) | `contents: write` | GitHub Release with the assets below |

The Release assets are `raftlab-X.Y.Z.zip`, `raftlab-X.Y.Z.tar` and `SHA256SUMS`. The release notes are generated by GitHub and grouped by the categories in `.github/release.yml`.

The images are `ghcr.io/<owner>/<repo>:X.Y.Z` and `ghcr.io/<owner>/<repo>:latest`. The `<owner>/<repo>` part is lowercased by the workflow.

## 3. Dry run

Run it from the Actions tab with Actions → Release → Run workflow, or with `gh workflow run release.yml --ref main`.

A dry run produces the version `0.0.0-dryrun.<run>`, the artifact `release-dist` (kept for 14 days), a Docker build followed by `scripts/check-image.sh`. It creates no Release and pushes nothing. The publish jobs are skipped by their `if:` conditions, and their first guard step also refuses to run unless the event is a `v*` tag push.

## 4. Local equivalent

Run these from the repository root:

```
./gradlew build -Praftlab.version=1.2.3
scripts/check-dist.sh raftlab-cli/build/distributions/raftlab-1.2.3.zip 1.2.3
docker build --build-arg RAFTLAB_VERSION=1.2.3 -t raftlab:1.2.3 .
scripts/check-image.sh raftlab:1.2.3 1.2.3
scripts/check-release-config.sh
```

Without the `raftlab.version` property, the version is `0.0.0-dev`.

## 5. Verifying a release

```
gh release download vX.Y.Z
sha256sum -c SHA256SUMS
```

On macOS, use `shasum -a 256 -c SHA256SUMS` instead of `sha256sum -c SHA256SUMS`.

Then unzip the `raftlab-X.Y.Z.zip` archive and run `bin/raftlab --version`. To check the image, run `docker pull ghcr.io/<owner>/<repo>:X.Y.Z` and then `docker run --rm ghcr.io/<owner>/<repo>:X.Y.Z --help`.

## 6. First-run caveats

These steps are manual. They are not done by the workflow.

- GHCR packages are private by default. Make the package public in the package's Package settings → Change visibility.
- The `org.opencontainers.image.source` label links the package to the repository.
- The jobs declare their own `permissions:`. An organization policy that forbids `packages: write` or `contents: write` still blocks publishing. Check Settings → Actions → General → Workflow permissions.
- Branch or tag protection must allow the user to push `v*` tags.
- The first tag run requires the tag to exist on the remote, because the Release step uses `--verify-tag`.

## 7. Post-push manual checklist

These checks are manual and are recorded in the milestone report.

1. A `workflow_dispatch` dry run is green. The `build` and `image-dry-run` jobs pass, the `release-dist` artifact is present, and the publish jobs are skipped.
2. The first `vX.Y.Z` tag run creates a Release with the zip, the tar, `SHA256SUMS` and categorized notes, and `sha256sum -c` passes. A `-rc` tag is marked as a pre-release.
3. `docker pull ghcr.io/<owner>/<repo>:X.Y.Z` works, then `docker run --rm IMAGE --help` and `--version` work. The package has been made public.
4. The `docker compose up --build` sequence from `docker/README.md` works: put and get, `kill n2`, reads still succeed, `start n2`, earlier data is readable, and `docker compose stop` exits cleanly.
